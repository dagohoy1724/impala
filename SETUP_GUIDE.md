# GitHub & Deployment Setup Guide

This guide details the post-push setup required in GitHub and Cloudflare for the `impala` project to run [`kebbbnnn/scholarship_scraper`](https://github.com/kebbbnnn/scholarship_scraper) on a daily schedule and keep scheduled GitHub Actions active.

---

## 1. GitHub Settings

Navigate to your repository: `https://github.com/dagohoy1724/impala`

### Step 1.1: Configure Persistent Turso Storage (Optional for Smoke Tests, Recommended for Daily Runs)

You can run the workflow immediately **without any secrets** (local SQLite + downloadable artifact mode). For daily scheduled runs to persist scholarship data into Turso Cloud:

**Using GitHub CLI (`gh`):**

```bash
turso db create scholarship-ph

gh secret set TURSO_DATABASE_URL --body "$(turso db show scholarship-ph --url)"
gh secret set TURSO_AUTH_TOKEN --body "$(turso db tokens create scholarship-ph)"
```

**Using the GitHub Web UI:**

1. In your GitHub repository, open **Settings**.
2. In the left sidebar, expand **Secrets and variables** and select **Actions**.
3. Under the **Repository secrets** tab, click **New repository secret** and add:
   - **`TURSO_DATABASE_URL`** — Remote Turso URL (`libsql://<db-name>-<org>.turso.io` or `https://<db-name>-<org>.turso.io`). *(Also accepted under **Variables** instead of **Secrets**.)*
   - **`TURSO_AUTH_TOKEN`** — JWT generated by `turso db tokens create <db-name>`.
4. Click **Add secret** after each entry.

### Step 1.2: Optional Scraper Source, Pinning, and Proxy Settings

If `kebbbnnn/scholarship_scraper` stays **public**, no checkout token is needed.

- **If you make `kebbbnnn/scholarship_scraper` private:**
  1. Generate a fine-grained PAT on the `kebbbnnn` account with **Contents: Read-only** access to `kebbbnnn/scholarship_scraper`.
  2. Save it in `dagohoy1724/impala` under **Settings -> Secrets and variables -> Actions -> Repository secrets** as **`SCRAPER_REPO_TOKEN`**.
- **Pinning a specific version (optional):**
  - Set repository variable **`SCRAPER_REF`** (under **Variables**) to a tag or full 40-character commit SHA instead of tracking `main`.
  - Override the upstream repo with repository variable **`SCRAPER_REPO`** (`owner/repo`) if you fork or rename it.
- **Optional proxy, dynamic LLM & crawl tuning:**
  - Secrets: `SCRAPER_PROXY_SERVER` *(also accepted as Variable)*, `SCRAPER_PROXY_USERNAME`, `SCRAPER_PROXY_PASSWORD`, `GHOST_BASE_URL` *(also accepted as Variable; optional external `ghost-server` URL if GitHub runner IPs hit Gemini rate limits)*
  - Variables: `SCRAPER_EXTRACTOR_MODE` (default `dynamic`; set `deterministic` to disable LLM calls on scheduled runs), `SCRAPER_LLM_MODEL` (default `gemini`), `SCRAPER_LLM_DELAY_SECONDS` (default `2.0`), `SCRAPER_LLM_TIMEOUT_SECONDS` (default `90`), `SCRAPER_LLM_MAX_CHARS` (default `24000`), `SCRAPER_MAX_PAGES_PER_SOURCE` (default `8`), `SCRAPER_MAX_CRAWL_DEPTH` (default `2`), `SCRAPER_TIMEZONE` (default `Asia/Manila`), `SCRAPER_HTTP_TIMEOUT_SECONDS` (default `25`), `SCRAPER_RATE_LIMIT_DELAY_SECONDS` (default `1.0`), `SCRAPER_BROWSER_SEED`

### Step 1.3: Enable Workflow Write Permissions (Required for Keep-Alive)

The in-repo keep-alive workflow (`keep-alive.yml`) checks weekly whether the latest commit is `>= 45` days old and pushes an empty heartbeat commit (`[skip ci]`) via `GITHUB_TOKEN` so the repository never hits GitHub's 60-day inactivity cutoff.

1. In your GitHub repository, open **Settings**.
2. In the left sidebar under **Code and automation**, click **Actions -> General**.
3. Scroll down to **Workflow permissions**.
4. Select **Read and write permissions**.
5. Click **Save**.

### Step 1.4: Keep Duplicate Schedules Disabled on `kebbbnnn/scholarship_scraper`

`kebbbnnn/scholarship_scraper` keeps the cron trigger in its own `.github/workflows/scrape.yml` disabled by default. Leave it disabled while `impala` is your scheduled runner writing to Turso Cloud so the two repositories never run concurrent scrapes against the same database.

## 2. Test Workflows Manually

### Test 1: Zero-Secret Curated Smoke Test (~20 seconds)

Verify checkout, `uv` installation, pipeline execution, Job Summary rendering, and artifact upload without touching external sites or downloading browser binaries:

1. Open the **Actions** tab in your repository.
2. In the left menu, click **Scholarship Collection Pipeline**.
3. Click **Run workflow**.
4. Set:
   - **`mode`**: `seed-curated`
   - **`fail_on_error`**: `true`
5. Click **Run workflow** and inspect the finished run:
   - The **Summary** tab shows the checked-out `scholarship_scraper` commit SHA, Scrape Summary table, and Database Statistics table.
   - The **Artifacts** section contains `scholarships-export-<run_number>-<run_attempt>` with `scholarships.json` (plus `scholarships.db` in local mode).

### Test 2: Live Scrape or Source Health Check

1. In **Actions -> Scholarship Collection Pipeline -> Run workflow**:
   - For a quick targeted live test, set **`mode`** to `live` and **`sources`** to `ched,dost-sei`.
   - For a non-mutating reachability/layout check, set **`mode`** to `health` and **`fail_on_error`** to `true`.
2. Or run via GitHub CLI (`gh`):

```bash
# Live run across all built-in + saved custom sources (dynamic Ghost Gemini extractor)
gh workflow run scrape.yml

# Ad-hoc single-site dynamic scrape via scrape-url
gh workflow run scrape.yml -f mode=live -f target_url=https://www.sm-foundation.org/what_we_do/college-scholarship-program/ -f max_pages=4 -f max_depth=1

# Targeted live run using deterministic extraction only with forced headless browser rendering
gh workflow run scrape.yml -f mode=live -f extractor=deterministic -f sources=ched,dost-sei -f force_browser=true

# Watch an active run and download its exported dataset artifact
gh run watch
gh run download --name "scholarships-export-<run_number>-<run_attempt>" --dir ./downloaded-export
```

### Test 3: Keep Scheduled Actions Alive

1. In the **Actions** tab, click **Keep Scheduled Actions Alive**.
2. Click **Run workflow** -> leave `force` unchecked -> click **Run workflow**.
3. Verify that the job finishes with status `0` and outputs:
   ```text
   Last commit age: 0 day(s) (threshold: 45 days).
   Repository is active; no keep-alive commit needed.
   ```
4. *(Optional)* Run once with `force` checked to verify push permissions immediately and confirm a `chore: keep-alive heartbeat [skip ci]` commit is pushed to `main`.

## 3. Schedule Reference

| Workflow | Trigger Schedule | Local Time | Purpose |
| --- | --- | --- | --- |
| `scrape.yml` | `7 18 * * *` | **02:07 AM PHT** (pre-shifted for **~09:00 AM PHT** execution after GitHub's ~7h cron queue lag) | Checks out `kebbbnnn/scholarship_scraper`, runs the live collection pipeline, persists to Turso (or local SQLite artifact), and publishes Job Summaries. |
| `keep-alive.yml` | `17 5 * * 1` | **01:17 PM PHT** (every Monday) | Checks latest commit age and pushes an empty `[skip ci]` heartbeat commit if `>= 45` days old. |

*Note: The Philippines (`Asia/Manila`, UTC+8) does not observe Daylight Saving Time (DST), so UTC offsets remain fixed year-round. Off-minute crons avoid top-of-hour (`:00`) GitHub Actions scheduler congestion.*

## 4. (Optional) External Cloudflare Worker Setup

This acts as a second, independent safety net against GitHub's 60-day inactivity policy for public repositories.

### Step 4.1: Update `wrangler.toml`

Edit `cloudflare-worker/wrangler.toml` and ensure `GITHUB_OWNER` matches your repository:

```toml
[vars]
GITHUB_OWNER = "dagohoy1724"
GITHUB_REPO = "impala"
```

Commit and push this change if not already done:
```bash
git add cloudflare-worker/wrangler.toml
git commit -m "chore: configure github owner for cloudflare worker"
git push origin main
```

### Step 4.2: Create a GitHub Personal Access Token (PAT)

1. Under your `dagohoy1724` account, navigate to **Settings -> Developer Settings -> Personal access tokens -> Fine-grained tokens**.
2. Click **Generate new token**.
3. Set:
   - **Token name:** `cloudflare-worker-keepalive`
   - **Repository access:** Selected repositories -> choose `dagohoy1724/impala`
   - **Permissions:** Under **Repository permissions**, set **Actions** to **Read and write**.
4. Generate and copy the token (`github_pat_...`).

### Step 4.3: Deploy the Worker via Wrangler

```bash
cd cloudflare-worker

# Login to Cloudflare
npx wrangler login

# Store the PAT as an encrypted secret
npx wrangler secret put GITHUB_TOKEN
# (paste the copied github_pat_... token when prompted)

# Deploy the worker
npx wrangler deploy
```

### Step 4.4: Test the Scheduled Event Locally (Optional)

```bash
cp .dev.vars.example .dev.vars
# Add GITHUB_TOKEN=github_pat_... in .dev.vars
npx wrangler dev --test-scheduled
```

In a separate terminal:
```bash
curl "http://localhost:8787/cdn-cgi/local/scheduled"
```

## 5. Troubleshooting & FAQ

### `TURSO_DATABASE_URL targets a remote Turso database, but the TURSO_AUTH_TOKEN secret is not set.`
- Cause: Only `TURSO_DATABASE_URL` was configured.
- Solution: Add `TURSO_AUTH_TOKEN` under **Settings -> Secrets and variables -> Actions -> Repository secrets**.

### `TURSO_AUTH_TOKEN secret is set, but the TURSO_DATABASE_URL secret is not set.`
- Cause: Only `TURSO_AUTH_TOKEN` was configured (or `TURSO_DATABASE_URL` was misspelled).
- Solution: Add `TURSO_DATABASE_URL` as a repository secret or variable (`libsql://<db-name>-<org>.turso.io`).

### `Turso authentication failed (HTTP 401)` or `HTTP 403`
- Cause: The token expired, was revoked, or belongs to a different database.
- Solution: Generate a new token (`turso db tokens create <db>`) and update `TURSO_AUTH_TOKEN`.

### `Checkout scholarship_scraper` fails with `Repository not found` or authentication error
- Cause: `kebbbnnn/scholarship_scraper` was made private (or `SCRAPER_REPO` / `SCRAPER_REF` is misspelled).
- Solution: Verify `SCRAPER_REPO` and `SCRAPER_REF`, and add a fine-grained PAT with **Contents: Read-only** access as the `SCRAPER_REPO_TOKEN` secret. Note that `uv sync` also fetches `kebbbnnn/ghost` over HTTPS, so `kebbbnnn/ghost` must remain public unless git credentials are configured for `uv sync`.

### Dynamic LLM extraction falls back to deterministic mode (`Ghost rate limited` / `fallback`)
- Cause: Anonymous `gemini.google.com` requests from GitHub Actions datacenter IPs hit rate limits or a CAPTCHA; the crawler's circuit breaker intentionally preserves prior hops and falls back to deterministic extraction.
- Solution: Configure `GHOST_BASE_URL` (secret or variable) pointing to an external `ghost-server`, lower `SCRAPER_MAX_PAGES_PER_SOURCE`, or set `vars.SCRAPER_EXTRACTOR_MODE=deterministic` for scheduled runs.

### `Unknown source(s): ...` (exit code `2`)
- Cause: Typo in the `sources` input (e.g., `dost` instead of `dost-sei`).
- Solution: Use the exact provider slugs or adapter keys from the table in Section 2.

### Source status is `blocked_challenge`
- Cause: The target site presented an active Cloudflare Turnstile / CAPTCHA gate. The scraper intentionally halts without bypassing it.
- Solution: Retry later, test `force_browser=true`, or configure `SCRAPER_PROXY_*` secrets if datacenter IPs are challenged.

### `invisible-playwright fetch` fails due to upstream release download error
- Cause: Transient GitHub Releases outage or engine pin mismatch.
- Solution: Re-run the workflow, or temporarily trigger with `-f browser_engine=playwright`.

### Schedule queue delay (cron didn't start at exactly 02:07 AM PHT)
- Cause: GitHub Actions scheduled events (`on: schedule`) run on shared public infrastructure and frequently experience queue delays during peak UTC windows. The `7 18 * * *` cron is intentionally pre-shifted to absorb this lag and finish by ~09:00 AM PHT.
